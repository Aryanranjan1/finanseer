# Finanseer

Welcome to Finanseer, a modern financial application designed to provide users with a comprehensive suite of tools for managing their finances, tracking investments, and exploring market data. This document provides an overview of the application, with a special focus on its current use of mock data and the frontend pages that are ready for backend integration.

## How Mock Data Works

The Finanseer frontend is currently powered by mock data, which allows for rapid prototyping and UI development without a live backend. This data is primarily sourced from two key files:

- `src/lib/data.ts`: This file contains a variety of mock data, including user testimonials, account features, and other static content used throughout the application. It serves as a placeholder for data that will eventually be fetched from a database or external APIs.

- `src/lib/page-data.ts`: This file provides the content for various pages, including titles, descriptions, and other text that will eventually be managed through a CMS or a backend service.

By using these files, we can develop and test the frontend in isolation, ensuring a seamless user experience before integrating with a live backend.

## Frontend Pages and Backend Integration

The following frontend pages have been developed and are currently using mock data. The next step is to connect them to a robust backend to enable full functionality.

### 1. User Authentication (Login and Signup)

- **Pages**: `src/app/login/page.tsx`, `src/app/signup/page.tsx`
- **Mocked Elements**: User authentication is currently simulated. The login and signup forms are fully designed, but they do not yet connect to an authentication service.
- **Backend Integration**: To enable real user accounts, the following backend functionality is required:
    - **User Registration**: An endpoint to handle new user signups, including data validation and password hashing.
    - **User Login**: An authentication endpoint that verifies user credentials and returns a session token (e.g., JWT).
    - **Password Reset**: A "forgot password" flow, including email verification and password reset functionality.

### 2. Main Dashboard (Overview)

- **Page**: `src/app/app/overview/page.tsx`
- **Mocked Elements**: The dashboard currently displays static data for portfolio value, recent transactions, and market trends.
- **Backend Integration**: The dashboard needs to be connected to the backend to display real-time user data:
    - **Portfolio Summary**: An endpoint to fetch the user's current portfolio value and performance metrics.
    - **Recent Transactions**: An endpoint to retrieve a list of the user's most recent transactions.
    - **Market Data**: Integration with a financial data API (e.g., Alpha Vantage, CoinGecko) to display live market charts and trends.

### 3. Portfolio Management

- **Page**: `src/app/app/portfolio/page.tsx`
- **Mocked Elements**: The portfolio page displays a static list of assets with mock quantities and values.
- **Backend Integration**: To provide a fully functional portfolio, the following backend services are needed:
    - **Asset Tracking**: Endpoints to add, edit, and remove assets from the user's portfolio.
    - **Real-Time Valuation**: A service to fetch real-time prices for the assets in the user's portfolio and calculate their total value.

### 4. Transactions History

- **Page**: `src/app/app/transactions/page.tsx`
- **Mocked Elements**: This page shows a hardcoded list of past transactions.
- **Backend Integration**: The transactions page requires the following backend functionality:
    - **Transaction Logging**: An endpoint to record new transactions (e.g., buy, sell, deposit, withdrawal).
    - **Transaction History**: An endpoint to fetch a paginated list of all transactions for the current user, with filtering and sorting options.

### 5. Market Insights and News

- **Page**: `src/app/insights/page.tsx`
- **Mocked Elements**: The market insights page displays static articles and news headlines.
- **Backend Integration**: To provide up-to-date market information, the following is needed:
    - **News Feed**: Integration with a news API to fetch and display the latest financial news.
    - **Market Analysis**: A service to provide market analysis and insights, which could be generated by an AI model or sourced from a financial data provider.

### 6. User Profile and Settings

- **Page**: `src/app/app/settings/page.tsx`
- **Mocked Elements**: The settings page has a UI for updating user information, but no changes are saved.
- **Backend Integration**: To allow users to manage their accounts, the following backend endpoints are necessary:
    - **User Profile**: Endpoints to get and update user profile information (e.g., name, email, password).
    - **Notification Preferences**: A service to manage user preferences for email and in-app notifications.

## Conclusion

The Finanseer frontend is well-structured and ready for backend integration. By focusing on the integration points outlined above, we can transition from a mock-data-driven application to a fully functional and dynamic financial tool. This new README.md provides a clear roadmap for the work ahead, ensuring that all developers have a shared understanding of the project's status and future direction.
